juuz is configured with environment variables. Booleans accept `1`, `true`, `yes`, `on`, `0`, `false`, `no` and `off`.

## Environment variables

| Variable              | Default               | Description                                                       |
| --------------------- | --------------------- | ----------------------------------------------------------------- |
| `JUUZ_ADMIN_PASSWORD` | random, logged once   | Password of the `admin` user. Only used on the first start       |
| `JUUZ_PUBLIC_URL`     | from the request      | Base URL for share links, for example `https://juuz.example.com`  |
| `JUUZ_TRUST_PROXY`    | `false`               | Use `X-Forwarded-For` as the client IP. Set only behind a reverse proxy that is the sole way to reach the port |
| `JUUZ_TOKEN_AUTH`     | `true`                | `false` turns off token login (`t` and `s`) and deletes the stored password secrets |
| `JUUZ_RATE_LIMIT`     | `1800`                | Requests per minute per IP. `0` turns it off                      |
| `JUUZ_SNAPCAST`       | `true`                | `false` turns off the Snapcast server on port `1704`              |
| `JUUZ_OMM`            | `true`                | Set `false` to stop sending track names to OpenMusicMetadata      |
| `JUUZ_LASTFM_API_KEY` | unset                 | Last.fm API key. Scrobbling is off without it                     |
| `JUUZ_LASTFM_SECRET`  | unset                 | Last.fm shared secret                                             |
| `RUST_LOG`            | `juuz=info,tower_http=warn` | Log filter                                                  |
| `NO_COLOR`            | unset                 | Disable colored log output                                        |

<Callout title="Reverse proxy" type="warn">
  Behind a proxy every request seems to come from the proxy. Set `JUUZ_TRUST_PROXY=true` so rate limits and failed login lockouts apply per client, and only if the proxy is the sole way to reach the port, otherwise clients can fake their IP.
</Callout>

<Callout title="Last.fm" type="info">
  Set both `JUUZ_LASTFM_API_KEY` and `JUUZ_LASTFM_SECRET`. With only one of them, Last.fm stays disabled and juuz logs a warning.
</Callout>

<Callout title="OpenMusicMetadata" type="info">
  With `JUUZ_OMM` on, juuz sends track details such as title, artist, album and duration to `https://api.vleer.app/metadata/v1` to match songs and fill in missing tags. Nothing is written to your files for matching alone. Set `JUUZ_OMM=false` to turn it off. See [OpenMusicMetadata](/openmusicmetadata) for the API.
</Callout>

## Scrobbling

Every `scrobble` from any app is forwarded to the services a user has linked, as now playing and as a scrobble. Links are per user and can be set on the `account` page or with the [scrobbling endpoints](/juuz/api#scrobbling).

### Last.fm

Create an API account at [last.fm/api](https://www.last.fm/api/account/create), set both variables and restart. Each user links their account once on the `account` page, or:

1. Call [`juuzLastfmAuthUrl`](/juuz/api#lastfm), open the returned `url` and allow access.
2. Call `juuzLastfmLink?token=<token>` with the returned `token`.

### ListenBrainz, Koito and Maloja

These need no server setup. Each user pastes their token on the `account` page and, for a self-hosted server, its URL. Leave the URL empty for listenbrainz.org.

| Service      | URL                                              |
| ------------ | ------------------------------------------------ |
| ListenBrainz | empty, or `https://api.listenbrainz.org`         |
| Koito        | `http://koito:4110/apis/listenbrainz`            |
| Maloja       | `http://maloja:42010/apis/listenbrainz`          |

juuz checks the token when linking. If a service later rejects it, juuz unlinks the account and logs a warning.

## Libraries

The `/music` folder is the first library. Admins and users with the library role can add more on the `server` page, and only admins can remove one. Each library has a name, a path, a writable flag and a scan interval, and users only see the libraries they were given access to.

Mount extra libraries outside `/music` and every other library, for example `/libraries/family`. Admins can add any folder. Other users with the library role can only add folders under `/libraries`. Uploads go to a writable library, see [Song upload](/juuz/upload#where-files-go).

Songs whose files disappear are kept until a user with the delete role removes them with the remove missing songs action on the `server` page, so a temporarily unmounted drive does not wipe stars and playlists.

## Folders

In the Docker image the working directory is `/`, so juuz uses `/data` and `/music`. When started elsewhere it uses `./data` and `./music` relative to the working directory.

| Path                    | Description                                              |
| ----------------------- | -------------------------------------------------------- |
| `music/`                | The first library. Scanned on start and watched for changes |
| `music/.juuz-tmp`       | Temporary files of in-progress uploads, one per library  |
| `data/juuz.db`          | SQLite database                                          |
| `data/secret.key`       | 32 byte key, created on first start with mode `0600`     |
| `data/cache/art`        | Cover art cache                                          |
| `data/cache/omm-art`    | Artwork fetched through OpenMusicMetadata                |
| `data/cache/transcode`  | Transcoded streams                                       |

<Callout title="Keep secret.key" type="warn">
  `secret.key` encrypts the stored passwords used for token login and the Last.fm session keys and ListenBrainz tokens. Back it up with the database. If it is lost, tokens stop working until each user logs in with a password again, and scrobbling accounts have to be linked again.
</Callout>

## Fixed defaults

These are not configurable yet.

| Setting                    | Value                        |
| -------------------------- | ---------------------------- |
| Listen address             | `0.0.0.0:4533`               |
| Library scan               | On start, then watched       |
| Song upload                | Enabled, up to 2 GiB         |
| Cover and lyrics upload    | Up to 10 MiB                 |
| Failed logins              | 10 per 5 minutes per IP, then locked |
| Rate limit burst           | 300 requests                 |
| Lyrics provider            | `https://lrclib.net/api`     |
